# JD 预算拆解参考与天猫落地边界

来源：`预算拆解0412.xlsx`。原表只作为预算建模结构参考，不是 EchoMerch 的运行时数据源。

## 可复用的规划结构

1. 总预算：先确定周期总预算，再拆分到计划类型或投放场景。
2. 渠道/场景分配：用预算占比形成第一层约束，合计应为 100%。
3. 商品/计划分配：每个场景继续拆到商品、计划或人群，层内占比合计应为 100%。
4. 分日预算：按日期展开，允许节点前后使用不同的日预算系数；日汇总应回勾到层级预算。
5. 节点备注：大促、上新、计划搭建、效果观察期等原因要和数字放在同一层，方便复盘调整。
6. 结构目标：关键词或人群可保留品牌词、品类词、智能词、商品定向等平台适配维度，但不能把京东名称硬编码到通用指标目录。

## 通用计算

- 层级预算 = 上级预算 × 层内预算占比。
- 分日预算 = 层级预算 × 日期节奏占比，或使用明确的日预算输入。
- 历史花费占比 = 该节点历史花费 / 节点总历史花费。
- 场景效率权重：以历史花费为基数，根据 ROI 与目标 ROI 的相对关系进行有限加权，再归一化到新预算。
- 场景预估成交 = 建议预算 × 历史 ROI；这只是情景估算，不是承诺。

## 必须保留的校验

- 所有层级占比合计应接近 100%，超过容差要标记异常。
- 总预算、场景预算、商品/计划预算和分日预算应逐层勾稽。
- ROI、预算消耗率和预估成交不能把缺失日期当成 0。
- 预算字段、毛利线、佣金、服务费、退款影响未采集时，相关绝对金额或盈利结论必须为 `null` 或明确标注为待输入。
- 原始工作簿存在 `#REF!` 断链时，不复制断链公式；要回到输入字段重新计算并标出缺失前置条件。

## 当前天猫边界

天猫标准化库已有场景、计划、人群、单元、关键词、商品和日期粒度的实际投放数据，可用于历史基准和建议比例。当前没有统一的“计划预算/日预算/毛利/佣金服务费约束”字段，因此 Skill 可以输出历史占比、目标占比和情景建议，但不会把历史花费当作新预算，也不会凭空生成预算消耗进度。
